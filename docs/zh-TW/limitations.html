已解決的問題與目前仍存在的限制，方便安裝前評估。

已解決

  • 風扇曲線座標。 改為畫布直接拖曳，點保持穩定，快取渲染會依內容變更失效（v0.3.0）。
  • USB-C 與 USB-A 分類。 曾回報 Sink role 的連接埠會固定為 USB-C，插拔擴充卡上的裝置不再翻轉類型（v0.3.0）。
  • 睡眠／休眠風扇控制。 Resume 會重置 EC client 與 curve stepper、每 30 秒重送 fan duty，並以 wall-clock jump fallback 涵蓋漏掉的 resume 事件（v0.3.0，v0.9.0 強化）。
  • MMIO mirror 設計上唯讀。 官方 Intel MCHBAR 模組只提供讀取，因此 Apply 只寫 MSR 0x610；mirror 仍用於顯示與 min(MSR, MMIO) 有效值估計。MSR 寫入已足夠本程式的 CPU 功耗控制。

未解決

  • AMD CPU Power 寫入為實驗性。 RyzenSMU 卡片可讀取 STAPM／PPT Fast／PPT Slow／Tctl 並套用 AC／Battery profiles，但要勾選「Enable experimental AMD writes」才會寫入。維護者沒有 AMD 硬體，各 CPU 世代的命令行為仍需社群驗證。
  • 測試平台有限。 只在 Intel Core Ultra Series 1（Meteor Lake）Framework 筆電測試；必須安裝 Framework EC kernel driver。
  • 逐風扇曲線缺少多風扇驗證。 只有模擬 EC 的單元測試 — 沒有 Framework 16／Desktop 硬體。單風扇機種走完全相同的既有路徑。
  • 崩潰會保留最後狀態。 正常退出會還原韌體風扇控制並 flush 充電上限；崩潰或強制終止會跳過該路徑，EC 會保留最後寫入的 fan duty，直到睡眠、重開機或下次啟動。
  • 登出交接不可靠。 部分 Windows 11 提權環境不會把 session-end broadcast 送到托盤視窗，手動／曲線 duty 可能在登出後持續。風扇由手動／曲線控制時，登出前請使用 Restore Auto & Exit。
  • 沒有 DP-alt 的 HDMI/DP 卡可能誤標。 連接埠類型由 PD 狀態推斷；省略 DP-alt 又消耗 ~3–5 W 的卡可能顯示錯誤標籤。About 頁的 Ports Debug Mode 可看原始 role／watts。
